# 2026-08-28

## 桌面宠物 Windows 多实例"被切掉下半身"Bug — 根因与架构级修复

### 根因结论（与用户截图分析一致）
- main 宠物窗口的可见形状由 WebView2 逐像素 alpha 提供（`tauri.conf.json` 已 `transparent:true` + 前端 `background:transparent`）。
- 旧实现用 `SetWindowRgn`（`windows_pet.rs::apply_hit_rects`）**同时**做硬裁切 + 点击穿透。
- 竞态：`SetWindowRgn` 即时改变窗口可见形状（系统级），而 WebView2/Chromium 合成器提交新帧是异步的，两者无同步。多实例并发时各窗口独立随机撞上竞态（二项分布），表现为"有的完整有的从眼睛位置被切、露桌面"。
- 排除：系统性 DPI bug（同机同刻不该有的完整有的残缺）；静态矩形算错（应为一致位置残缺，而非随机）。

### 已实施的修复（path 1：架构级根治）
- 移除 main 窗口一切 `SetWindowRgn`；窗口保持整块透明矩形，可见形状全交给 WebView2 alpha。
- 命中测试改用 `WM_NCHITTEST` 子类：`install_hit_test_subclass` 在 main 窗口**及其 WebView2 子窗口**上子类化，`hit_test_subclass` 在点击时实时读 `HIT_RECTS`：区域内 `HTCLIENT`、区域外 `HTTRANSPARENT`（穿透到桌面）。渲染与穿透彻底解耦。
- 关键 gotcha：只子类化主窗口不够——鼠标落 WebView2 子 HWND 时 `WM_NCHITTEST` 先到子窗口，需 `EnumChildWindows` 找到它一并子类化（按类名 `WebView2`/`Chrome_WidgetWin` 匹配，否则取面积最大子窗口兜底）。
- 改动文件：`src-tauri/src/windows_pet.rs`、`src-tauri/src/main.rs`（`resize_pet_window` 去掉重裁、`setup_notify_interactive` 改装子类）、`Cargo.toml`（windows-sys 增 `Win32_UI_Shell`）。

### 待 Windows 真机验证
- 本机 macOS 无法编译/运行 `cfg(windows)` 代码；已手工核对 windows-sys 0.52 类型与模块路径（见下），但运行时行为（穿透、拖拽、多开）需在 Windows 构建确认。
