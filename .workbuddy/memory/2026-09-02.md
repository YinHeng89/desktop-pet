## windows_pet.rs 跨平台 dead_code 告警修复（方案 A）
- 现象：`cargo run`（macOS）报 3 个 `dead_code` 告警：`HIT_RECTS`/`RECTS_INITIALIZED`/`store_hit_rects` never used。
- 根因：3 项均为 Windows-only，但声明在模块顶层、无 `#[cfg(target_os="windows")]` 守卫。macOS 编译时 `apply_hit_rects`（读取 static 的唯一定义，行 211 已 `#[cfg(windows)]`）不编译，且 `store_hit_rects` 唯一调用方 `interactive.rs:17` 也 `#[cfg(windows)]`，故 macOS 下全死。
- 修复：给 `use std::sync::Mutex`、`use crate::domain::geometry::Rect`、`HIT_RECTS`、`RECTS_INITIALIZED`、`store_hit_rects` 共 5 处加 `#[cfg(target_os="windows")]`。`Mutex`/`Rect` 仅被这三项使用，一并加守卫避免 unused-import。
- 验证：`cargo check --no-default-features` 干净无告警；Windows 行为不变。

## clippy 门禁缺口修复（verify 与 CI 对齐）
- 现象：本地 `npm run verify` 全绿，但 quality.yml 的 `rust` / `rust-windows` 两个 job 跑 `cargo clippy -- -D warnings` 报错 → CI 红。
- 根因：本地 `verify` 只跑 `cargo test`，**从不跑 clippy**；而 CI 跑 clippy。所以 clippy lint 在本地漏检。
- 真实错误：`notify_server.rs` 里 `if let Err(_) = std::thread::Builder::new().spawn(...)` 触发 `redundant_pattern_matching`（跨平台编译，两个 job 都炸），改为绑定变量后 `.is_err()`。
- 修复：package.json 新增 `lint:rust` 并接入 `verify`；`.prettierignore` 排除 `.workbuddy`（本地记忆被 prettier 误报导致 format:check 失败）。
- 教训：**本地 verify 门禁必须覆盖 CI 的全部 `-D warnings` 步骤（尤其 clippy）**，否则必然出现「本地绿、CI 红」。Windows-only cfg 分支的 clippy 只能靠 quality.yml 的 `rust-windows` job 验证，本地 macOS 跑不到，提交前无法 100% 保证。

## macos_pet.rs 跨平台 dead_code 修复（CI 实测报错）
- 现象：quality.yml 的 `rust`(Linux) 与 `rust-windows`(Windows) job 均报 `error: static RECTS_DIRTY is never used`(macos_pet.rs:41) 与 `error: function store_interactive_rects is never used`(macos_pet.rs:60)，`cargo clippy -D warnings` 编译失败 exit 101/1。
- 根因：与 windows_pet.rs 同款 —— 两项均为 macOS-only，但声明在模块顶层、无 `#[cfg(target_os="macos")]` 守卫。`store_interactive_rects` 唯一调用方是 `interactive.rs:15`（已 `#[cfg(target_os="macos")]` 包裹），`RECTS_DIRTY` 唯一消费者是 `macos_impl::tick_inner`（整块 `#[cfg(macos)]`），故非 macOS 编译期全死。
- 修复：仅给这 2 项加 `#[cfg(target_os = "macos")]`（与文件内 `:46/:96/:497` 既有约定一致）。**不**动 `Mutex`/`Rect`/`point_in_rects` import 及 `INTERACTIVE_RECTS`/`RECTS_INITIALIZED`——它们仍被顶层 `#[allow(dead_code)]` 的 `hit_interactive`/`rects_initialized` 引用，非 macOS 下仍是「被引用」状态，误 gate 会冒 unused-import。
- 验证：本地 macOS `npm run verify` 全绿（含 clippy）。非 macOS 路径靠引用链推理确认无连带 unused-import。
- 规律：跨平台模块里「被 cfg 专属函数/调用方独占的 static 与 fn」必须同层加 cfg 守卫；而「被跨平台 `#[allow(dead_code)]` 函数引用的 static」则保持 ungated。
